# 추억 장소 아카이브 만들기 1편

이번 시리즈에서는 **내가 다녀온 장소와 그곳에서의 추억을 기록하는 웹 서비스**를 만들어 봅니다.
단순히 장소 이름만 저장하는 것이 아니라, **주소 / 지역 / 한 줄 추억 / 감정 / 대표 이미지 / 좌표(latitude, longitude)** 까지 함께 저장해서 이후 편에서 더 풍부한 기능으로 확장할 예정입니다.

이번 1편에서는 아직 사용자가 직접 장소를 검색해서 저장하는 단계까지 가지 않습니다.
먼저 **프로젝트의 뼈대**를 단단히 만드는 데 집중합니다.

즉, 이번 편의 핵심은 아래 3가지입니다.

* **Place 모델 설계하기**
* **관리자페이지에서 장소 데이터 관리하기**
* **메인 화면 / 목록 화면에 저장된 장소 출력하기**

---

## 이번 편에서 완성할 결과물

이번 글을 끝내면 아래 상태까지 완성됩니다.

* Django 프로젝트와 앱이 준비된다.
* `Place` 모델을 만들고 마이그레이션할 수 있다.
* 관리자페이지에서 추억 장소 데이터를 등록할 수 있다.
* 등록한 장소를 메인 화면과 목록 화면에서 볼 수 있다.
* 다음 편에서 회원 기능과 장소 검색 UX를 붙일 수 있는 기본 구조가 갖춰진다.

---

## 왜 1편에서 먼저 모델과 관리자페이지를 만들까요?

많은 초보자분들이 바로 화면부터 만들고 싶어 합니다.
물론 화면을 먼저 보는 것도 재미있지만, **데이터 구조가 먼저 정해지지 않으면 이후 기능이 계속 흔들리게 됩니다.**

예를 들어 이번 프로젝트에서는 나중에 이런 기능이 추가될 예정입니다.

* 장소 검색 후 **장소명 / 주소 / 지역 자동 입력**
* 장소 선택 시 **위도(latitude), 경도(longitude) 자동 저장**
* 같은 감정의 장소 추천
* 지도 위에 저장한 장소 핀 표시

이런 기능을 자연스럽게 붙이려면, 1편에서부터 모델 필드를 미리 잘 설계해 두는 것이 중요합니다.

즉, 이번 편은 단순한 준비 단계가 아니라
**앞으로 2~5편이 매끄럽게 이어지도록 만드는 핵심 설계 편**이라고 보면 됩니다.

# 3. Place 모델 설계하기

이제 가장 중요한 `Place` 모델을 만들어 보겠습니다.

이번 프로젝트는 단순한 장소 목록이 아니라 **추억을 담는 장소 아카이브**입니다.
그래서 장소 자체의 정보와 감정적인 정보가 함께 들어가야 합니다.

예를 들어 아래 같은 데이터를 저장하고 싶습니다.

* 서울숲
* 서울 성동구
* 처음 같이 산책했던 장소
* 설렘
* 2024-04-12 방문
* 썸네일 이미지
* 위도 / 경도

이런 구조를 생각하며 필드를 설계하면 됩니다.

---

## 3-1. 모델 코드 작성하기

```python title="places/models.py"
from django.db import models


class Place(models.Model):
    EMOTION_CHOICES = [
        ('설렘', '설렘'),
        ('그리움', '그리움'),
        ('힐링', '힐링'),
        ('기쁨', '기쁨'),
        ('사색', '사색'),
        ('아련함', '아련함'),
    ]

    title = models.CharField(max_length=100, verbose_name='장소명')
    address = models.CharField(max_length=255, blank=True, verbose_name='주소')
    region = models.CharField(max_length=100, blank=True, verbose_name='지역')
    memory_line = models.CharField(max_length=200, verbose_name='한 줄 추억')
    description = models.TextField(blank=True, verbose_name='상세 설명')
    emotion = models.CharField(
        max_length=20,
        choices=EMOTION_CHOICES,
        default='설렘',
        verbose_name='감정',
    )
    image = models.ImageField(upload_to='places/', blank=True, null=True, verbose_name='대표 이미지')
    visited_date = models.DateField(blank=True, null=True, verbose_name='방문 날짜')
    latitude = models.DecimalField(
        max_digits=10,
        decimal_places=7,
        blank=True,
        null=True,
        verbose_name='위도',
    )
    longitude = models.DecimalField(
        max_digits=10,
        decimal_places=7,
        blank=True,
        null=True,
        verbose_name='경도',
    )
    is_featured = models.BooleanField(default=False, verbose_name='추천 장소 여부')
    created_at = models.DateTimeField(auto_now_add=True, verbose_name='생성일')
    updated_at = models.DateTimeField(auto_now=True, verbose_name='수정일')

    class Meta:
        ordering = ['-created_at']
        verbose_name = '추억 장소'
        verbose_name_plural = '추억 장소들'

    def __str__(self):
        return self.title
```

---

## 3-2. 각 필드 설명

### `title`

장소 이름입니다.
예: 서울숲, 해운대해수욕장, 경복궁

### `address`

상세 주소입니다.
2편에서 카카오맵 검색 결과로 자동 입력받을 예정입니다.

### `region`

지역명입니다.
예: 서울, 부산, 제주

### `memory_line`

이 프로젝트의 감성 포인트입니다.
그 장소를 한 문장으로 기억할 수 있게 저장합니다.

예:

* 처음 같이 걸었던 산책길
* 비 오는 날 혼자 생각 정리하러 갔던 곳
* 졸업식 끝나고 친구들과 마지막으로 모였던 카페

### `description`

한 줄 추억보다 더 자세한 설명을 담는 필드입니다.

### `emotion`

장소를 대표하는 감정을 저장합니다.
나중에 같은 감정의 장소 추천 기능에도 활용할 수 있습니다.

### `image`

대표 이미지입니다.
아직 1편에서는 관리자페이지로 업로드하는 수준이지만, 이후 화면 완성도를 높이는 데 아주 중요합니다.

### `visited_date`

언제 갔던 장소인지 기록하는 날짜 필드입니다.

### `latitude`, `longitude`

이 필드는 이번 시리즈에서 매우 중요합니다.

왜냐하면 이후에:

* 장소 검색 후 좌표 자동 저장
* 지도 위에 핀 표시
* 위치 기반 시각화

기능을 하려면 반드시 필요하기 때문입니다.

이번 1편에서는 값이 비어 있어도 괜찮습니다.
하지만 **모델에는 미리 포함해 두는 것**이 맞습니다.

### `is_featured`

추천 장소 여부입니다.
메인 페이지에서 대표 장소를 보여줄 때 활용할 수 있습니다.

### `created_at`, `updated_at`

정렬, 최신순 표시, 관리자페이지 관리 등에 유용합니다.

---

## 3-3. 왜 좌표 필드를 처음부터 넣어야 할까요?

이번 프로젝트는 나중에 단순 목록 앱이 아니라 **지도 기반 서비스**로 확장될 예정입니다.

즉, 사용자는 2편에서 장소를 검색하고,
그 선택 결과로 아래 값들이 자동 입력될 예정입니다.

* 장소명
* 주소
* 지역
* 위도
* 경도

그리고 마지막 5편에서는 저장된 위도/경도를 이용해서 **대한민국 지도 위에 핀을 표시**하게 됩니다.

그래서 좌표 필드는 나중에 급하게 덧붙이는 것보다, 1편부터 미리 설계해 두는 것이 더 자연스럽습니다.

# 6. 관리자페이지(admin)에 모델 등록하기

이제 `Place` 모델을 관리자페이지에 등록해 보겠습니다.

## 6-1. 기본 등록

```python title="places/admin.py"
from django.contrib import admin
from .models import Place


admin.site.register(Place)
```

이렇게만 해도 관리자페이지에서 `Place` 모델이 보이기는 합니다.
하지만 지금은 너무 기본형이라 실제로 쓰기엔 조금 불편합니다.

그래서 바로 커스터마이징을 해보겠습니다.

---

## 6-2. 관리자페이지 커스터마이징

```python title="places/admin.py"
from django.contrib import admin
from django.utils.html import format_html
from .models import Place


@admin.register(Place)
class PlaceAdmin(admin.ModelAdmin):
    list_display = (
        'id',
        'title',
        'region',
        'emotion',
        'is_featured',
        'image_preview',
        'visited_date',
        'created_at',
    )
    search_fields = ('title', 'address', 'region', 'memory_line')
    list_filter = ('emotion', 'region', 'is_featured', 'visited_date')
    ordering = ('-created_at',)
    readonly_fields = ('created_at', 'updated_at', 'image_preview')
    fields = (
        'title',
        'address',
        'region',
        'memory_line',
        'description',
        'emotion',
        'image',
        'image_preview',
        'visited_date',
        'latitude',
        'longitude',
        'is_featured',
        'created_at',
        'updated_at',
    )

    def image_preview(self, obj):
        if obj.image:
            return format_html('<img src="{}" width="100" style="border-radius:8px;" />', obj.image.url)
        return '이미지 없음'

    image_preview.short_description = '썸네일 미리보기'
```

---

## 6-3. 이 설정이 왜 좋은가요?

### `list_display`

목록에서 어떤 컬럼을 보여줄지 정합니다.
관리자 입장에서 빠르게 데이터 상태를 파악할 수 있습니다.

### `search_fields`

검색창으로 장소명, 주소, 지역, 한 줄 추억을 검색할 수 있습니다.

### `list_filter`

감정, 지역, 추천 여부 등으로 필터링할 수 있어 관리가 훨씬 쉬워집니다.

### `readonly_fields`

생성일, 수정일처럼 직접 수정할 필요 없는 값은 읽기 전용으로 두는 것이 안전합니다.

### `image_preview`

대표 이미지를 작은 썸네일로 바로 확인할 수 있어서 아주 편합니다.

이런 커스터마이징은 단순한 꾸미기가 아니라,
**데이터를 실제로 관리하기 쉽게 만드는 실무적인 설정**입니다.

# 7. URL 연결하기

이제 웹 화면을 위한 URL을 연결하겠습니다.

## 7-1. 프로젝트 URL에 앱 URL 연결

```python title="config/urls.py"
from django.conf import settings
from django.conf.urls.static import static
from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('places.urls')),
]

if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

여기서 `static(settings.MEDIA_URL, ...)` 부분은 개발환경에서 업로드한 이미지가 보이도록 하는 설정입니다.

> 아직 places/views.py를 작성하지 않았기에, runserver시 에러가 발생합니다.

# 8. View 작성하기

이제 데이터를 화면으로 보내는 View를 작성합니다.

```python title="places/views.py"
from django.shortcuts import render
from .models import Place


def home(request):
    featured_places = Place.objects.filter(is_featured=True)[:3]
    latest_places = Place.objects.all()[:6]
    return render(
        request,
        'places/home.html',
        {
            'featured_places': featured_places,
            'latest_places': latest_places,
        },
    )


def place_list(request):
    places = Place.objects.all()
    return render(request, 'places/place_list.html', {'places': places})
```

---

## 8-1. View 설명

### `home`

메인 페이지입니다.

* 추천 장소 3개
* 최신 장소 6개

를 보여주도록 구성했습니다.

### `place_list`

전체 장소 목록 페이지입니다.
아직 페이지네이션은 적용하지 않았고, 전체 목록을 그대로 보여주는 단순 버전입니다.

페이지네이션은 3편에서 더 자연스럽게 붙일 예정입니다.

# 15. 자주 막히는 오류 포인트

## 15-1. `no such table: places_place`

마이그레이션을 하지 않았거나, 적용이 제대로 되지 않았을 때 발생합니다.

```bash title="terminal"
python manage.py makemigrations
python manage.py migrate
```

다시 실행해 보세요.

---

## 15-2. 이미지가 보이지 않아요

`MEDIA_URL`, `MEDIA_ROOT`, `static(settings.MEDIA_URL, ...)` 설정이 빠졌을 가능성이 큽니다.

반드시 아래 두 군데를 확인하세요.

* `config/settings.py`
* `config/urls.py`

---

## 15-3. 관리자페이지에서 `Place`가 안 보여요

`INSTALLED_APPS`에 `places`가 빠졌거나, `admin.py` 등록이 빠졌을 가능성이 큽니다.

---

## 15-4. `TemplateDoesNotExist`

템플릿 파일 경로나 이름이 맞는지 확인하세요.

특히 이번 교안에서는 다음 경로를 정확히 맞춰야 합니다.

```text title="template paths"
templates/base.html
templates/places/home.html
templates/places/place_list.html
```

---

## 15-5. 이미지 업로드 시 `Pillow` 관련 오류

`pillow` 설치 여부를 확인하세요.

```bash title="terminal"
pip install pillow
```

# 16. 이번 편에서 꼭 기억해야 할 핵심

이번 편의 가장 중요한 포인트는 아래 4가지입니다.

## 1) 모델을 먼저 설계해야 이후 기능이 흔들리지 않는다

특히 이번 프로젝트처럼 지도, 추천, 검색 기능이 확장될 예정이라면 더 중요합니다.

## 2) 좌표 필드는 1편부터 넣는 것이 맞다

2편에서 장소 검색 결과로 위도/경도를 자동 입력하고, 5편에서 지도 위에 핀을 찍기 위해 필요합니다.

## 3) 관리자페이지는 단순 부가기능이 아니다

오히려 초기 개발 단계에서는 데이터를 가장 빠르게 넣고 검증할 수 있는 강력한 도구입니다.

## 4) 템플릿도 처음부터 너무 밋밋하지 않게 만드는 것이 좋다

실습 결과물이 눈에 보여야 동기부여가 커집니다.

# 18. 마무리

이번 1편에서는 **추억 장소 아카이브 프로젝트의 가장 중요한 기초 공사**를 마쳤습니다.

아직은 사용자가 직접 장소를 검색해서 저장하지는 않지만,
그 기능이 자연스럽게 붙을 수 있도록 아래를 미리 준비했습니다.

* 장소명 / 주소 / 지역 필드
* 감정 / 한 줄 추억 필드
* 이미지 필드
* 좌표(latitude, longitude) 필드
* 관리자페이지 관리 구조
* 메인 / 목록 템플릿 구조

이제 다음 편에서는 진짜 사용자 입장에서 더 자연스러운 흐름을 만들 차례입니다.

즉, **회원가입 / 로그인 / 함수형 CRUD**를 붙이고,
무엇보다도 **카카오맵 장소 검색을 이용해 장소명·주소·지역·좌표를 자동으로 입력하는 UX**를 만들어 보겠습니다.
