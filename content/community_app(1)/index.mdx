# 커뮤니티 게시판 프로젝트 1편

## 프로젝트 시작, 구조 설계, 앱 생성, 공통 설정

게시판 프로젝트는 **회원가입 / 로그인 / 게시글 / 댓글 / 좋아요 / 파일 업로드 / 카테고리 / 검색 / 필터 / 페이지네이션**까지 포함하는 **커뮤니티 서비스**입니다.

그리고 이번 3차 프로젝트는 나중에 4차 프로젝트에서 아래와 같은 구조로 확장될 예정입니다.

```
사용자 요청
→ Django 서비스 서버 처리
→ DB 저장
→ FastAPI AI 서버 요청
→ Celery + Redis 비동기 처리
→ 결과 저장
→ 화면 출력
```

지금 만드는 1편은 **4차 프로젝트 확장까지 이어질 뼈대**를 만드는 단계입니다.

그래서 이번 편에서는 기능을 급하게 많이 넣지 않고, 앞으로 흔들리지 않을 구조를 먼저 정확하게 세팅하겠습니다.

---

# 이번 편에서 만들 것

이번 1편에서는 아래 내용을 완성합니다.

```
1. 프로젝트 생성
2. 앱 생성
3. settings.py 기본 설정
4. templates / static / media 구조 만들기
5. 공통 base.html 작성
6. 메인 페이지 연결
7. CSS 연결
```

아직 이번 편에서는 회원가입이나 게시글 CRUD를 만들지 않습니다.

왜냐하면 지금은 **기능을 넣기 전에 구조를 먼저 만드는 단계**이기 때문입니다.

---

# 이번 편이 중요한 이유

처음 Django 프로젝트를 시작하면 학생들이 가장 많이 헷갈리는 부분은 아래 3가지입니다.

1. 어떤 앱을 왜 나누는지 모르겠다.
2. templates / static / media가 각각 무슨 역할인지 모르겠다.
3. 파일이 많아지기 시작하면 어디에 무엇을 넣어야 하는지 모르겠다.

그래서 이번 편에서는 이 혼란을 줄이기 위해 아래 원칙을 먼저 잡고 시작합니다.

## 이번 프로젝트의 기본 원칙

* 앱은 역할 기준으로 나눈다.
* HTML, CSS, JS는 분리한다.
* 업로드 파일을 위한 media 구조를 미리 잡아둔다.
* 공통 레이아웃을 먼저 만들어서 이후 편마다 반복 코드를 줄인다.
* 처음부터 너무 다양한 기능보다 **재사용 가능한 구조**를 만든다.

# 이번 프로젝트에서 사용할 앱 구조

이번 프로젝트에서는 아래 3개 앱으로 시작하겠습니다.

* `accounts` : 회원가입, 로그인, 로그아웃
* `posts` : 게시글, 카테고리, 파일 업로드, 목록/상세/검색/필터/페이지네이션
* `interactions` : 댓글, 좋아요

이 구조가 좋은 이유는 아래와 같습니다.

## 왜 이렇게 나누는가?

### 1. accounts

사용자 인증 기능은 대부분의 프로젝트에서 독립적인 역할을 합니다.

회원가입 / 로그인 / 로그아웃은 게시글 기능과 연결되긴 하지만, 성격이 다릅니다.
그래서 따로 분리하는 것이 좋습니다.

### 2. posts

커뮤니티 서비스의 핵심 데이터는 게시글입니다.
카테고리, 첨부파일, 목록 조회, 검색, 필터 등은 모두 게시글을 중심으로 움직입니다.
그래서 중심 도메인 앱으로 `posts`를 둡니다.

### 3. interactions

댓글과 좋아요는 게시글 그 자체라기보다, 게시글에 대한 **사용자 행동**입니다.
그래서 따로 분리해두면 나중에 구조가 훨씬 깔끔해집니다.

# 7단계. settings.py 전체 수정

이제 가장 중요한 설정 파일을 정리하겠습니다.

이번 1편에서는 아래를 한 번에 반영합니다.

* 앱 등록
* django-environ 적용
* templates 경로 설정
* static 경로 설정
* media 경로 설정
* 로그인/로그아웃 리다이렉트 기본값 설정
* DRF 설치만 반영

아래는 이번 편 기준 최종 `settings.py` 전체 코드입니다.

```python title="config/settings.py"
from pathlib import Path
import environ

BASE_DIR = Path(__file__).resolve().parent.parent

env = environ.Env()
environ.Env.read_env(BASE_DIR / ".env")

SECRET_KEY = env("SECRET_KEY", default="django-insecure-fallback-key")
DEBUG = env.bool("DEBUG", default=True)

ALLOWED_HOSTS = []

INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",
    "rest_framework",
    "accounts",
    "posts",
    "interactions",
]

MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "django.contrib.sessions.middleware.SessionMiddleware",
    "django.middleware.common.CommonMiddleware",
    "django.middleware.csrf.CsrfViewMiddleware",
    "django.contrib.auth.middleware.AuthenticationMiddleware",
    "django.contrib.messages.middleware.MessageMiddleware",
    "django.middleware.clickjacking.XFrameOptionsMiddleware",
]

ROOT_URLCONF = "config.urls"

TEMPLATES = [
    {
        "BACKEND": "django.template.backends.django.DjangoTemplates",
        "DIRS": [BASE_DIR / "templates"],
        "APP_DIRS": True,
        "OPTIONS": {
            "context_processors": [
                "django.template.context_processors.request",
                "django.contrib.auth.context_processors.auth",
                "django.contrib.messages.context_processors.messages",
            ],
        },
    },
]

WSGI_APPLICATION = "config.wsgi.application"

DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.sqlite3",
        "NAME": BASE_DIR / "db.sqlite3",
    }
}

AUTH_PASSWORD_VALIDATORS = [
    {
        "NAME": "django.contrib.auth.password_validation.UserAttributeSimilarityValidator",
    },
    {
        "NAME": "django.contrib.auth.password_validation.MinimumLengthValidator",
    },
    {

    },
    {
        "NAME": "django.contrib.auth.password_validation.NumericPasswordValidator",
    },
]

LANGUAGE_CODE = "ko-kr"
TIME_ZONE = "Asia/Seoul"
USE_I18N = True
USE_TZ = True

STATIC_URL = "/static/"
STATICFILES_DIRS = [BASE_DIR / "static"]

MEDIA_URL = "/media/"

DEFAULT_AUTO_FIELD = "django.db.models.BigAutoField"
```

# settings.py 설명

이제 위 코드가 왜 필요한지 하나씩 설명하겠습니다.

## 1. environ 설정

```python
import environ
env = environ.Env()
environ.Env.read_env(BASE_DIR / ".env")
```

이 코드는 `.env` 파일의 값을 읽기 위한 설정입니다.

즉, 비밀키나 운영 환경 설정을 코드에 직접 적지 않고 외부 파일에서 읽게 만들기 위한 준비입니다.

---

## 2. INSTALLED_APPS

```python
"rest_framework",
"accounts",
"posts",
"interactions",
```

* `rest_framework`는 나중에 DRF에서 사용합니다.
* `accounts`, `posts`, `interactions`는 우리가 만든 앱입니다.

여기에 등록하지 않으면 Django가 해당 앱을 프로젝트 일부로 인식하지 못합니다.

---

## 3. TEMPLATES DIRS

```python
"DIRS": [BASE_DIR / "templates"],
```

이 설정 덕분에 프로젝트 루트의 `templates` 폴더를 Django가 찾을 수 있습니다.

즉, `templates/base.html`, `templates/home.html` 같은 공용 템플릿을 쉽게 사용할 수 있습니다.

---

## 4. STATICFILES_DIRS

```python
STATICFILES_DIRS = [BASE_DIR / "static"]
```

이 설정은 CSS, JS, 이미지 같은 정적 파일을 `static` 폴더에서 찾도록 만드는 설정입니다.

이번 교안에서는 CSS를 HTML에 직접 쓰지 않고, 꼭 `static/css/style.css`로 분리할 것이므로 매우 중요합니다.

---

## 5. MEDIA 설정

```python
MEDIA_URL = "/media/"
MEDIA_ROOT = BASE_DIR / "media"
```

이 설정은 사용자가 업로드하는 파일을 저장할 위치를 정합니다.

아직 1편에서는 실제 업로드 기능을 만들지 않지만, 이후 파일 업로드를 붙일 예정이므로 지금부터 준비해둡니다.

---

## 6. LOGIN 관련 설정

```python
LOGIN_URL = "accounts:login"
LOGIN_REDIRECT_URL = "home"
LOGOUT_REDIRECT_URL = "home"
```

이 부분은 나중에 로그인/로그아웃 기능을 만들었을 때,
로그인 후 어디로 갈지, 로그아웃 후 어디로 갈지를 기본값으로 미리 잡아둔 것입니다.

즉, 이후 편에서 View 코드를 훨씬 간단하게 만들 수 있습니다.

# 8단계. 메인 화면 View 만들기

이번 편에서는 아직 별도 앱의 View를 쓰기보다, 프로젝트 전체에서 사용하는 아주 간단한 메인 화면부터 연결하겠습니다.

먼저 `config/views.py` 파일을 새로 만듭니다.

```python title="config/views.py"
from django.views.generic import TemplateView


class HomeView(TemplateView):
    template_name = "home.html"
```

## 왜 TemplateView를 쓰는가?

이번 프로젝트는 앞으로 Generic View를 사용할 예정입니다.

이번 1편에서도 가장 단순한 형태의 제네릭 뷰인 `TemplateView`를 먼저 써보겠습니다.

# 10단계. 프로젝트 전체 URL 연결

이제 프로젝트의 메인 URL 파일을 정리하겠습니다.

아래는 이번 편 기준 최종 `config/urls.py` 전체 코드입니다.

```python title="config/urls.py"
from django.conf import settings
from django.conf.urls.static import static
from django.contrib import admin
from django.urls import include, path

from config.views import HomeView

urlpatterns = [
    path("admin/", admin.site.urls),
    path("", HomeView.as_view(), name="home"),
    path("accounts/", include("accounts.urls")),
    path("posts/", include("posts.urls")),
    path("interactions/", include("interactions.urls")),
]

    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

# config/urls.py 설명

## 1. 메인 페이지 연결

```python
path("", HomeView.as_view(), name="home")
```

사이트 첫 화면(`/`)으로 접속했을 때 `HomeView`가 실행됩니다.

---

## 2. 앱별 URL 분리

```python
path("accounts/", include("accounts.urls")),
path("posts/", include("posts.urls")),
path("interactions/", include("interactions.urls")),
```

이 구조 덕분에 나중에

* 회원가입 / 로그인은 `accounts/`
* 게시글은 `posts/`
* 댓글 / 좋아요는 `interactions/`

이렇게 역할별로 URL을 깔끔하게 분리할 수 있습니다.

---

## 3. media 파일 개발 환경에서 보기

```python
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

이 코드는 개발 중 업로드한 파일을 브라우저에서 볼 수 있게 해줍니다.

4편 파일 업로드에서 꼭 필요하므로 지금부터 미리 넣어두는 것이 좋습니다.

# base.html 설명

## 1. `{% load static %}`

Django 템플릿에서 CSS 파일을 연결하려면 static 태그를 불러와야 합니다.

```html
{% load static %}
```

이 줄이 없으면 CSS 경로를 Django 방식으로 연결할 수 없습니다.

---

## 2. 블록 구조

```html
{% block title %}{% endblock %}
{% block content %}{% endblock %}
```

이 구조 덕분에 각 페이지가 base.html을 상속하면서,
페이지마다 제목과 본문 내용만 다르게 넣을 수 있습니다.

즉, 앞으로 회원가입 페이지, 로그인 페이지, 게시글 목록 페이지도 모두 이 틀을 재사용하게 됩니다.

---

## 3. 네비게이션 메뉴를 지금부터 만드는 이유

지금은 아직 링크가 비어 있는 메뉴가 있어도 괜찮습니다.

앞으로 해당 링크를 하나씩 실제 기능 페이지로 연결 할 거에요.
