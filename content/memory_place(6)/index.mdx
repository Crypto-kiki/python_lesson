# 추억 장소 아카이브 만들기 6편

<a href="https://python-lesson-red.vercel.app/blogs/memory_place(5)" target="_blank">이전 교안 보기</a>

지난 5편에서는 DRF를 이용해 **생성 / 수정 / 삭제 API** 까지 완성했습니다.

즉 지금 프로젝트는 아래 기능을 모두 갖춘 상태입니다.

* 장소 등록 / 수정 / 삭제
* 카카오 장소 검색 자동입력
* 작성자(author) 연결
* 웹 CRUD
* DRF CRUD
* 로그인 / 권한 처리

여기까지 오면 이제 데이터 저장 구조는 꽤 단단해졌습니다.

이제 유저 경험을 향상시킬 수 있는 방법은 뭐가 있을까요?

> “내가 기록한 장소들이 지도 위에서 보이면 훨씬 재미있지 않을까?”

실제로 장소 아카이브 서비스에서 가장 중요한 경험 중 하나는,
내가 다녀온 장소들이 **지도 위에 점처럼 쌓이는 경험** 입니다.

특히 지금 프로젝트는 이미 아래 데이터를 저장하고 있습니다.

* 위도(latitude)
* 경도(longitude)
* 장소명(title)
* 주소(address)
* 지역(region)

즉 지도 기능을 붙일 준비가 이미 끝난 상태입니다.

그래서 이번 6편에서는,
저장된 장소 데이터를 **카카오맵 전국지도 위에 마커(pin)** 로 표시해보겠습니다.

이번 편에서 구현할 핵심은 아래입니다.

* 메인페이지에 대한민국 전체 지도 보여주기
* 전체 장소 보기 페이지에 대한민국 전체 지도 보여주기
* DB에 저장된 모든 장소를 마커로 표시하기
* 마커를 클릭하면 해당 장소 상세 페이지로 이동할 수 있게 만들기

즉 이번 편부터는,
추억 장소 아카이브가 단순히 카드 목록으로 끝나는 서비스가 아니라,
**지도 기반 아카이브 서비스**처럼 보이기 시작합니다.

---

## 이번 편에서 완성할 결과물

이번 글을 끝내면 아래 상태까지 완성됩니다.

* 메인페이지에 대한민국 전체 지도를 띄운다.
* 전체 장소 보기 페이지에도 전국지도를 띄운다.
* DB에 저장된 모든 장소를 지도 위 마커로 표시한다.
* 마커를 클릭하면 장소명과 지역을 확인할 수 있다.
* 마커 클릭 시 상세 페이지로 이동할 수 있다.
* 좌표가 없는 장소는 지도 마커에서 자동 제외한다.
* 카드 목록 + 지도 구조가 함께 보이도록 UI를 정리한다.

# 0. 이번 편 전체 흐름 먼저 보기

## 이번 편 실습 순서

1. 왜 지금 지도 기능을 붙이는지 이해하기
2. 카카오맵 전체 지도 표시 전략 이해하기
3. DB의 장소 데이터를 템플릿에 JSON으로 넘기기
4. 메인페이지에 전국지도 붙이기
5. 전체 장소 보기 페이지에도 전국지도 붙이기
6. 모든 장소를 마커로 표시하기
7. 마커 클릭 시 상세 페이지로 이동하기
8. 카드 목록과 지도 UI를 함께 다듬기
9. 자주 발생하는 오류와 디버깅 포인트 정리하기
10. 다음 편 마이페이지 확장 방향 확인하기

이번 편의 핵심 기술은 아래입니다.

* Kakao Maps JavaScript SDK
* Django 템플릿에서 JSON 데이터 전달
* 저장된 위도 / 경도 기반 마커 렌더링
* 마커 클릭 이벤트 처리

# 1. 왜 6편에서 전국지도 기능을 붙이나요?

지금까지는 장소를 저장하고, 수정하고, API로 조회하는 흐름을 만들었습니다.

즉 “데이터를 관리하는 구조”는 이미 충분히 준비되었습니다.

이제부터는 사용자가 이 데이터를 **어떻게 더 직관적으로 경험하느냐** 가 중요해집니다.

장소 아카이브 서비스에서 카드 목록만 보는 것과,
전국지도 위에 방문 기록이 하나씩 쌓이는 것을 보는 경험은 꽤 다릅니다.

지도 기능이 붙으면 아래 장점이 생깁니다.

* 내가 어느 지역을 많이 기록했는지 한눈에 보인다.
* 장소 데이터가 단순 텍스트가 아니라 공간 정보로 느껴진다.
* 서비스가 더 완성도 있어 보인다.
* 다음 단계(마이페이지, 필터, 지역별 탐색)로 확장하기 쉬워진다.

특히 이번 프로젝트는 이미 카카오 장소 검색으로 좌표를 자동 저장하고 있기 때문에,
지금이 지도 기능을 붙이기에 가장 좋은 타이밍입니다.

# 2. 이번 편에서 지도는 어떻게 구성할까요?

* 마커 클러스터링
* 커스텀 오버레이 디자인
* 실시간 필터링
* 카드와 마커 완전 동기화

이번 6편에서는 **전국지도 + 전체 마커 표시** 에 집중합니다.

즉 구현 범위는 아래로 잡습니다.

## 메인페이지

* 대한민국 전체 지도 표시
* 저장된 모든 장소 마커 표시

## 전체 장소 보기 페이지

* 전국지도 표시
* 저장된 모든 장소 마커 표시
* 아래에는 기존 장소 카드 목록 유지

즉 이번 편은 “전체 장소를 지도 위에서 본다”가 핵심입니다.

그리고 다음 7편에서,
같은 패턴을 활용해 **마이페이지 + 내 장소만 표시** 로 확장하면 됩니다.

# 3. places/views.py 에서 지도용 데이터 준비하기

지도에서 마커를 찍으려면,
템플릿에 단순 QuerySet만 넘겨서는 자바스크립트에서 바로 쓰기 불편할 수 있습니다.

그래서 이번에는 템플릿에서 쓰기 좋은 형태로,
장소 데이터를 리스트 형태로 가공해서 넘겨주겠습니다.

기존 `places/views.py` 를 아래처럼 수정합니다.

```python title="places/views.py"
from django.conf import settings
from django.contrib import messages
from django.contrib.auth import login
from django.contrib.auth.mixins import LoginRequiredMixin, UserPassesTestMixin
from django.shortcuts import redirect, render
from django.urls import reverse_lazy
from django.views.generic import CreateView, DeleteView, DetailView, ListView, TemplateView, UpdateView

from .forms import PlaceForm, SignUpForm
from .models import Place


class HomeView(TemplateView):
    template_name = 'places/home.html'

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        featured_places = Place.objects.filter(is_featured=True)[:3]
        latest_places = Place.objects.select_related('author').all()[:6]
        map_places = Place.objects.exclude(latitude__isnull=True).exclude(longitude__isnull=True)

        context['featured_places'] = featured_places
        context['latest_places'] = latest_places
        context['kakao_javascript_key'] = settings.KAKAO_JAVASCRIPT_KEY
        context['map_places'] = [
            {
                'id': place.id,
                'title': place.title,
                'region': place.region or '지역 정보 없음',
                'address': place.address or '주소 정보 없음',
                'latitude': float(place.latitude),
                'longitude': float(place.longitude),
            }
            for place in map_places
        ]
        return context


class PlaceListView(ListView):
    model = Place
    template_name = 'places/place_list.html'
    context_object_name = 'places'
    paginate_by = 6

    def get_queryset(self):
        return Place.objects.select_related('author').all().order_by('-created_at')

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        map_places = Place.objects.exclude(latitude__isnull=True).exclude(longitude__isnull=True)
        context['kakao_javascript_key'] = settings.KAKAO_JAVASCRIPT_KEY
        context['map_places'] = [
            {
                'id': place.id,
                'title': place.title,
                'region': place.region or '지역 정보 없음',
                'address': place.address or '주소 정보 없음',
                'latitude': float(place.latitude),
                'longitude': float(place.longitude),
            }
            for place in map_places
        ]
        return context


class PlaceDetailView(DetailView):
    model = Place
    template_name = 'places/place_detail.html'
    context_object_name = 'place'

    def get_queryset(self):
        return Place.objects.select_related('author').all()


class PlaceCreateView(LoginRequiredMixin, CreateView):
    model = Place
    form_class = PlaceForm
    template_name = 'places/place_form.html'

    def form_valid(self, form):
        form.instance.author = self.request.user
        messages.success(self.request, '새로운 추억 장소가 등록되었습니다.')
        return super().form_valid(form)

    def get_success_url(self):
        return reverse_lazy('places:place_detail', kwargs={'pk': self.object.pk})

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context['page_title'] = '장소 기록 추가'
        context['submit_label'] = '장소 저장하기'
        context['kakao_javascript_key'] = settings.KAKAO_JAVASCRIPT_KEY
        return context


class AuthorRequiredMixin(UserPassesTestMixin):
    def test_func(self):
        place = self.get_object()
        return place.author == self.request.user

    def handle_no_permission(self):
        messages.error(self.request, '본인 글만 수정하거나 삭제할 수 있습니다.')
        return redirect('places:place_list')


class PlaceUpdateView(LoginRequiredMixin, AuthorRequiredMixin, UpdateView):
    model = Place
    form_class = PlaceForm
    template_name = 'places/place_form.html'
    context_object_name = 'place'

    def form_valid(self, form):
        form.instance.author = self.request.user
        messages.success(self.request, '추억 장소가 수정되었습니다.')
        return super().form_valid(form)

    def get_success_url(self):
        return reverse_lazy('places:place_detail', kwargs={'pk': self.object.pk})

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context['page_title'] = '장소 기록 수정'
        context['submit_label'] = '수정 내용 저장하기'
        context['kakao_javascript_key'] = settings.KAKAO_JAVASCRIPT_KEY
        return context


class PlaceDeleteView(LoginRequiredMixin, AuthorRequiredMixin, DeleteView):
    model = Place
    template_name = 'places/place_confirm_delete.html'
    context_object_name = 'place'
    success_url = reverse_lazy('places:place_list')

    def delete(self, request, *args, **kwargs):
        messages.success(self.request, '추억 장소가 삭제되었습니다.')
        return super().delete(request, *args, **kwargs)



def signup(request):
    if request.user.is_authenticated:
        return redirect('places:home')

    if request.method == 'POST':
        form = SignUpForm(request.POST)
        if form.is_valid():
            user = form.save()
            login(request, user)
            messages.success(request, '회원가입이 완료되었습니다. 바로 로그인되었습니다.')
            return redirect('places:home')
    else:
        form = SignUpForm()

    return render(request, 'registration/signup.html', {'form': form})
```

## 3-1. 왜 `map_places` 를 따로 만들까요?

카드 목록용 QuerySet과,
지도에 바로 뿌릴 JSON용 데이터는 목적이 조금 다릅니다.

지도에서는 주로 아래 값만 있으면 됩니다.

* id
* title
* region
* address
* latitude
* longitude

즉 템플릿 안에서 자바스크립트가 다루기 좋은 형태로 미리 정리해두는 것입니다.

또한 `latitude`, `longitude` 는 자바스크립트에서 숫자로 써야 하므로,
`float()` 로 변환해두는 것이 좋습니다.

---

## 3-2. 좌표 없는 데이터는 왜 제외하나요?

```python title="places/views.py"
map_places = Place.objects.exclude(latitude__isnull=True).exclude(longitude__isnull=True)
```

좌표가 없는 장소는 지도 위에 정확한 위치를 표시할 수 없습니다.

그래서 이번 편에서는,
**위도와 경도가 모두 있는 장소만 지도 마커 대상으로 사용**합니다.

이런 예외 처리를 미리 해두면,
자바스크립트에서 `NaN`, `undefined` 같은 문제를 줄일 수 있습니다.

## 4-1. `json_script` 를 쓰는 이유

이 부분은 꼭 이해해야 합니다.

```html title="templates/places/home.html"
{{ map_places|json_script:'home-map-places-data' }}
```

Django 템플릿에서 파이썬 리스트를 자바스크립트로 넘길 때,
그냥 문자열처럼 넣으면 따옴표 문제나 XSS 이슈가 생길 수 있습니다.

`json_script` 는 데이터를 비교적 안전하게 JSON 형태로 심어주는 방식입니다.

즉,

* 템플릿에서는 `map_places` 를 JSON으로 숨겨두고
* 자바스크립트에서는 `JSON.parse(...)` 로 꺼내서 사용

하는 구조입니다.

이 방식은 지도, 차트, 그래프, 프론트엔드 데이터 전달에서 매우 자주 씁니다.

---

## 4-2. 왜 지도 중심 좌표를 `36.35, 127.8` 정도로 잡았나요?

대한민국 전체를 대략 보기 좋은 중심값을 잡은 것입니다.

서울만 보여주려는 것이 아니라,
전국 지도를 자연스럽게 보여주려면 너무 북쪽/남쪽으로 치우치지 않은 중심값이 필요합니다.

즉 이번 편에서는 “정확한 행정 중심점”보다,
**대한민국 전체가 보기 좋게 들어오는 지도 중심** 을 기준으로 잡았습니다.

## 4-3. 마커 클릭 시 상세 페이지 이동

이 부분은 UX에서 꽤 중요합니다.

```javascript title="templates/places/home.html"
kakao.maps.event.addListener(marker, 'click', function () {
  window.location.href = `/places/${place.id}/`;
});
```

즉 마커는 단순 표시만 하는 것이 아니라,
사용자가 클릭하면 바로 해당 장소의 상세 기록으로 들어갈 수 있습니다.

이렇게 해두면 지도와 카드 목록이 따로 노는 것이 아니라,
지도도 탐색 인터페이스 역할을 하게 됩니다.

# 9. 자주 발생하는 오류와 디버깅 포인트

## 9-1. 지도가 아예 안 보이는 경우

가장 먼저 아래를 확인합니다.

* `kakao_javascript_key` 가 템플릿에 정상 전달되는지
* `.env` 의 키가 올바른지
* `settings.py` 에서 환경변수를 잘 읽고 있는지
* SDK 스크립트 태그가 제대로 들어갔는지

예:

```html title="template snippet"
<script src="//dapi.kakao.com/v2/maps/sdk.js?appkey={{ kakao_javascript_key }}"></script>
```

---

## 9-2. 마커가 하나도 안 찍히는 경우

대부분 아래 중 하나입니다.

* `map_places` 가 비어 있음
* latitude / longitude 값이 비어 있음
* 템플릿 JSON 파싱이 제대로 안 됨

먼저 DB에 실제 좌표 값이 저장된 장소가 있는지 확인하세요.

---

## 9-3. 자바스크립트 에러가 나는 경우

브라우저 개발자도구 콘솔을 확인합니다.

자주 생기는 실수:

* `JSON.parse(...)` 대상 element id 오타
* `homeNationwideMap`, `placeListNationwideMap` id 오타
* `latitude`, `longitude` 가 숫자가 아니라 문자열/빈값

---

## 9-4. 상세 페이지 이동이 안 되는 경우

```javascript title="template snippet"
window.location.href = `/places/${place.id}/`;
```

이 경로가 현재 URL 구조와 맞는지 확인합니다.

현재 프로젝트에서는 상세 페이지 URL이 `/places/<pk>/` 이므로 위 코드가 맞습니다.

---

## 9-5. 지도가 너무 확대되거나 너무 축소되어 보이는 경우

초기 중심 좌표와 level 값을 조금 조절하면 됩니다.

예:

```javascript title="template snippet"
center: new kakao.maps.LatLng(36.35, 127.8),
level: 13,
```

프로젝트 데이터가 많아지면 이후에 `setBounds()` 로 자동 범위를 맞추는 고도화도 가능합니다.
하지만 이번 편에서는 전국지도 감각을 우선 유지하기 위해 고정값으로 시작합니다.

# 11. 체크리스트

아래 항목이 전부 되면 이번 편은 성공입니다.

* ✅ 메인페이지에 전국지도가 보인다.
* ✅ 전체 장소 보기 페이지에도 전국지도가 보인다.
* ✅ 좌표가 있는 장소들이 마커로 표시된다.
* ✅ 마커에 마우스를 올리면 장소명/지역이 보인다.
* ✅ 마커 클릭 시 상세 페이지로 이동한다.
* ✅ 좌표가 없는 장소는 자동으로 제외된다.
* ✅ 카드 목록과 지도 UI가 함께 자연스럽게 보인다.
* ✅ 모바일에서도 지도 영역이 크게 깨지지 않는다.

# 12. 마무리

이번 6편에서는,
지금까지 저장해둔 장소 데이터를 **대한민국 전국지도 위에 시각화** 했습니다.

이번 편에서 특히 중요한 것은,
우리가 새 기능을 위해 전혀 새로운 데이터를 만든 것이 아니라는 점입니다.

이미 2-2편에서 장소 검색 자동입력으로 저장해둔 아래 정보가 있었기 때문에,
이번 지도 기능이 가능해졌습니다.

* 위도
* 경도
* 장소명
* 주소
* 지역

즉 이번 편은,
지금까지 쌓아온 데이터 구조를 활용해서
프로젝트의 완성도를 크게 끌어올린 확장편이라고 볼 수 있습니다.

이제 추억 장소 아카이브는 단순한 카드 목록 서비스가 아니라,
**지도 위에서 공간적으로 탐색할 수 있는 아카이브 서비스**처럼 보이기 시작했습니다.

마지막 7편에서는 이번 전국지도 구조를 이어서,
**마이페이지 만들기 + 내가 기록한 장소만 지도에 표시하기 + 필터링** 을 구현해보겠습니다.

즉 다음 편부터는,
전체 장소를 보는 경험에서 한 단계 더 나아가
**“내 아카이브”를 따로 모아 보는 개인화 화면** 및 필터를 만들게 됩니다.
