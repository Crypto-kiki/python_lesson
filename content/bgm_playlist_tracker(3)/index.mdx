# Django 기초 - BGM 플레이리스트 기록기 만들기(3) : 제너릭 View로 정리하고 DRF API까지 확장하기

<a href="https://python-lesson-red.vercel.app/blogs/bgm_playlist_tracker(2)" target="_blank">➡️ 이전 교안 보러가기</a>

이번 3편에서는 2편에서 만든 **함수형 View 기반 CRUD 웹앱**을 한 단계 더 발전시켜,
이제 Django스럽게 **제너릭 View로 다시 정리**하고,
같은 데이터를 **Django REST Framework(DRF) API**로도 제공해보겠습니다.

즉 이번 편은 단순히 기능을 하나 더 붙이는 것이 아니라,
기존 웹앱을 **리팩토링하고 확장하는 단계**라고 보면 됩니다.

이번 3편에서 새롭게 다룰 내용은 아래와 같습니다.

* 함수형 View를 제너릭 View로 전환하기
* 템플릿 웹앱은 그대로 유지하면서 코드 구조 정리하기
* Django REST Framework 설치 및 연결하기
* `Serializer` 만들기
* `ViewSet` 만들기
* `Router`로 API URL 자동 연결하기
* 브라우저와 API 테스트 도구로 CRUD API 확인하기

이번 편이 끝나면 사용자는 아래 두 흐름을 모두 가지게 됩니다.

```
브라우저 웹앱으로 곡 등록 / 조회 / 수정 / 삭제
→ 그리고
API로도 곡 목록 조회 / 상세 조회 / 생성 / 수정 / 삭제
```

즉 1편이 **모델과 목록 화면**,
2편이 **함수형 View CRUD 완성**이었다면,
이번 3편은 **제너릭 View + DRF API 확장** 단계입니다.

# 0. 이번 교안의 진짜 목표

이번 교안의 핵심은 단순히 DRF를 설치해보는 데 있지 않습니다.

실제로는 아래 5가지를 익히는 것이 중요합니다.

| 목표            | 설명                                               |
| ------------- | ------------------------------------------------ |
| 제너릭 View 이해   | Django가 제공하는 공통 CRUD View를 사용해 반복 코드를 줄이는 법을 익힌다 |
| 기존 코드 리팩토링 경험 | 이미 돌아가는 함수형 View 코드를 제너릭 View로 바꾸는 흐름을 익힌다       |
| 웹과 API의 역할 구분 | 템플릿 기반 웹 화면과 JSON API의 차이를 이해한다                  |
| DRF 핵심 구성 이해  | Serializer, ViewSet, Router가 각각 무슨 역할을 하는지 이해한다  |
| API 테스트 경험    | GET, POST, PUT/PATCH, DELETE 요청을 직접 확인해본다        |

이번 편에서 꼭 머릿속에 남겨야 할 흐름은 아래입니다.

```
기존 함수형 CRUD 확인
→ 제너릭 View로 리팩토링
→ 웹 동작 다시 확인
→ DRF 설치
→ Serializer 작성
→ ViewSet 작성
→ Router 연결
→ API 테스트
```

이 흐름을 익혀두면 이후 Django 프로젝트에서
웹 화면과 API를 함께 운영하는 구조를 훨씬 쉽게 이해할 수 있습니다.

# 4. 왜 제너릭 View로 다시 정리할까?

2편에서는 함수형 View로 CRUD를 직접 구현했습니다.
그 방식은 Django의 기본 동작을 이해하기에 아주 좋습니다.

하지만 프로젝트가 조금만 커져도 아래 문제가 생깁니다.

* 비슷한 코드가 반복됨
* 공통 흐름을 직접 계속 작성해야 함
* 등록 / 수정 / 삭제 같은 표준 패턴에서 코드 양이 늘어남

그래서 Django는 이런 반복을 줄이기 위해 **제너릭 View**를 제공합니다.

대표적으로 아래 클래스들을 자주 사용합니다.

* `ListView`
* `DetailView`
* `CreateView`
* `UpdateView`
* `DeleteView`

즉 아래처럼 생각하면 됩니다.

```
함수형 View는 흐름 이해에 좋다
→ 제너릭 View는 반복 줄이기에 좋다
→ 실무에서는 둘 다 이해하고 있어야 한다
```

# 6. forms.py 다시 확인하기

이번 3편에서도 등록/수정 화면은 기존 `SongForm`을 그대로 사용합니다.

```python title="music/forms.py"
from django import forms
from .models import Song


class SongForm(forms.ModelForm):
    class Meta:
        model = Song
        fields = ["artist", "title", "rating", "comment", "youtube_url"]
        widgets = {
            "artist": forms.TextInput(
                attrs={
                    "class": "form-input",
                    "placeholder": "가수명을 입력하세요",
                }
            ),
            "title": forms.TextInput(
                attrs={
                    "class": "form-input",
                    "placeholder": "곡 제목을 입력하세요",
                }
            ),
            "rating": forms.NumberInput(
                attrs={
                    "class": "form-input",
                    "min": 1,
                    "max": 5,
                    "placeholder": "1 ~ 5",
                }
            ),
            "comment": forms.Textarea(
                attrs={
                    "class": "form-textarea",
                    "rows": 5,
                    "placeholder": "이 곡을 좋아하는 이유를 적어보세요",
                }
            ),
            "youtube_url": forms.URLInput(
                attrs={
                    "class": "form-input",
                    "placeholder": "https://www.youtube.com/watch?v=...",
                }
            ),
        }
```

즉 제너릭 View로 바꾼다고 해서 폼까지 새로 만드는 것은 아닙니다.
기존에 잘 만들어둔 `SongForm`을 그대로 재사용하면 됩니다.

# 7. views.py를 제너릭 View 기준으로 전체 수정하기

이제 `music/views.py`를 함수형 View 대신 제너릭 View 기반으로 다시 작성하겠습니다.

```python title="music/views.py"
from urllib.parse import parse_qs, urlparse

from django.urls import reverse_lazy
from django.views.generic import CreateView, DeleteView, DetailView, ListView, UpdateView

from .forms import SongForm
from .models import Song


class SongListView(ListView):
    model = Song
    template_name = "music/song_list.html"
    context_object_name = "songs"
    ordering = ["-created_at"]


class SongDetailView(DetailView):
    model = Song
    template_name = "music/song_detail.html"
    context_object_name = "song"

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        video_id = extract_youtube_video_id(self.object.youtube_url)
        context["embed_url"] = (
            f"https://www.youtube.com/embed/{video_id}" if video_id else None
        )
        return context


class SongCreateView(CreateView):
    model = Song
    form_class = SongForm
    template_name = "music/song_form.html"

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context["mode"] = "create"
        return context

    def get_success_url(self):
        return reverse_lazy("music:song_detail", kwargs={"pk": self.object.pk})


class SongUpdateView(UpdateView):
    model = Song
    form_class = SongForm
    template_name = "music/song_form.html"

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context["mode"] = "update"
        context["song"] = self.object
        return context

    def get_success_url(self):
        return reverse_lazy("music:song_detail", kwargs={"pk": self.object.pk})


class SongDeleteView(DeleteView):
    model = Song
    template_name = "music/song_confirm_delete.html"
    context_object_name = "song"
    success_url = reverse_lazy("music:song_list")



def extract_youtube_video_id(url):
    if not url:
        return None

    parsed_url = urlparse(url)

    if "youtu.be" in parsed_url.netloc:
        return parsed_url.path.lstrip("/")

    if "youtube.com" in parsed_url.netloc:
        query = parse_qs(parsed_url.query)
        if "v" in query:
            return query["v"][0]

        path_parts = parsed_url.path.split("/")
        if "embed" in path_parts:
            embed_index = path_parts.index("embed")
            if embed_index + 1 < len(path_parts):
                return path_parts[embed_index + 1]

    return None
```

# 8. 제너릭 View 코드 하나씩 이해하기

## 8-1. 목록은 `ListView`

```python title="music/views.py"
class SongListView(ListView):
    model = Song
    template_name = "music/song_list.html"
    context_object_name = "songs"
    ordering = ["-created_at"]
```

이 코드는 아래 역할을 합니다.

* `Song` 목록 조회
* `music/song_list.html` 템플릿 렌더링
* 템플릿에서 `songs`라는 이름으로 사용 가능
* 최신 등록 곡이 위로 오도록 정렬

즉 2편의 `song_list(request)` 함수형 View를,
이제 클래스 하나로 정리한 것입니다.

---

## 8-2. 상세는 `DetailView`

```python title="music/views.py"
class SongDetailView(DetailView):
```

등록 후에는 아래처럼 방금 생성된 상세페이지로 이동시킵니다.

```python title="music/views.py"
def get_success_url(self):
    return reverse_lazy("music:song_detail", kwargs={"pk": self.object.pk})
```

---

## 8-4. 수정은 `UpdateView`

```python title="music/views.py"
class SongUpdateView(UpdateView):
    model = Song
    form_class = SongForm
    template_name = "music/song_form.html"
```

수정 화면은 등록과 거의 비슷하지만,
이미 존재하는 객체를 불러와서 폼에 채워준다는 점이 다릅니다.

즉 같은 `song_form.html` 템플릿을 재사용하면서,
`mode = "update"`를 내려주어 제목이나 버튼 문구만 다르게 처리하면 됩니다.

# 9. urls.py를 제너릭 View 기준으로 전체 수정하기

이제 `music/urls.py`도 새 구조에 맞게 다시 작성합니다.

```python title="music/urls.py"
from django.urls import include, path
from rest_framework.routers import DefaultRouter

from .api_views import SongViewSet
from .views import (
    SongCreateView,
    SongDeleteView,
    SongDetailView,
    SongListView,
    SongUpdateView,
)

app_name = "music"

router = DefaultRouter()
router.register("songs", SongViewSet, basename="song-api")

urlpatterns = [
    path("", SongListView.as_view(), name="song_list"),
    path("create/", SongCreateView.as_view(), name="song_create"),
    path("<int:pk>/", SongDetailView.as_view(), name="song_detail"),
    path("<int:pk>/edit/", SongUpdateView.as_view(), name="song_update"),
    path("<int:pk>/delete/", SongDeleteView.as_view(), name="song_delete"),
    path("api/", include(router.urls)),
]
```

# 11. settings.py에 DRF 등록하기

Django REST Framework를 사용하려면 먼저 설치가 필요합니다.

## 설치 명령어

### Windows

```bash title="terminal"
pip install djangorestframework
```

### macOS

```bash title="terminal"
pip install djangorestframework
```

설치가 끝났다면 `INSTALLED_APPS`에 아래 앱을 추가합니다.

```python title="config/settings.py"
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",
    "music",
    "rest_framework",
]
```

여기서 중요한 것은 **`rest_framework`를 반드시 추가해야** 한다는 점입니다.
이걸 빼먹으면 API 페이지가 정상적으로 동작하지 않습니다.

# 12. serializers.py 전체 작성하기

이제 `Song` 모델을 JSON으로 변환하기 위한 Serializer를 작성하겠습니다.

```python title="music/serializers.py"
from rest_framework import serializers

from .models import Song


class SongSerializer(serializers.ModelSerializer):
    class Meta:
        model = Song
        fields = [
            "id",
            "artist",
            "title",
            "rating",
            "comment",
            "youtube_url",
            "created_at",
            "updated_at",
        ]
```

---

# 13. Serializer는 왜 필요할까?

Django 모델 객체는 그대로는 JSON 응답으로 바로 보내기 어렵습니다.
그래서 DRF에서는 **Serializer**가 중간에서 변환 역할을 합니다.

즉 아래처럼 이해하면 됩니다.

```
Song 모델 객체
→ Serializer
→ JSON 응답
```

반대로 POST나 PATCH 요청이 들어왔을 때는,
JSON 데이터를 검사해서 다시 Django 모델로 저장하는 역할도 합니다.

즉 Serializer는 단순 출력 도구가 아니라,
**검증 + 변환 + 저장 연결**까지 담당하는 아주 중요한 구성요소입니다.

---

# 14. api_views.py 전체 작성하기

이제 API용 ViewSet을 작성하겠습니다.

```python title="music/api_views.py"
from rest_framework import viewsets

from .models import Song
from .serializers import SongSerializer


class SongViewSet(viewsets.ModelViewSet):
    queryset = Song.objects.all().order_by("-created_at")
    serializer_class = SongSerializer
```

---

# 15. ViewSet은 왜 좋을까?

`ModelViewSet`은 CRUD API를 한 번에 묶어서 제공하기 좋습니다.

아래 동작들이 자동으로 연결됩니다.

* 목록 조회 `GET /api/songs/`
* 단일 조회 `GET /api/songs/1/`
* 생성 `POST /api/songs/`
* 전체 수정 `PUT /api/songs/1/`
* 일부 수정 `PATCH /api/songs/1/`
* 삭제 `DELETE /api/songs/1/`

즉 함수형 API View를 여러 개 만드는 대신,
ViewSet 하나로 표준 CRUD API를 깔끔하게 관리할 수 있습니다.

# 23. 웹과 API의 차이 한 번에 정리하기

같은 `Song` 데이터를 다루더라도,
웹 View와 API ViewSet은 역할이 다릅니다.

| 구분       | 역할         | 결과       |
| -------- | ---------- | -------- |
| 제너릭 View | 템플릿 렌더링    | HTML 페이지 |
| ViewSet  | 데이터 API 제공 | JSON 응답  |

즉 아래처럼 생각하면 됩니다.

```
웹 View는 사람이 화면으로 보는 용도
API ViewSet은 프로그램이 데이터로 쓰는 용도
```

이 둘을 함께 운영할 수 있어야 이후 프론트엔드 분리 프로젝트나 모바일 앱 연동도 이해하기 쉬워집니다.

# 24. 자주 만나는 오류 정리

## 24-1. `ModuleNotFoundError: No module named 'rest_framework'`

DRF가 설치되지 않았거나,
가상환경이 다른 상태에서 서버를 실행했을 가능성이 큽니다.

가장 먼저 아래를 확인하세요.

```bash title="terminal"
pip install djangorestframework
```

---

## 24-2. `/api/songs/`가 404일 때

가장 먼저 `music/urls.py`에서 아래 부분을 확인해야 합니다.

```python title="music/urls.py"
path("api/", include(router.urls)),
```

그리고 `config/urls.py`에서 `music.urls`가 include되어 있는지도 확인해야 합니다.

---

## 24-3. Serializer import 오류가 날 때

`music/api_views.py`에서 아래 import 경로를 확인하세요.

```python title="music/api_views.py"
from .serializers import SongSerializer
```

파일명이 `serializer.py`인지 `serializers.py`인지 오타가 자주 납니다.

---

## 24-4. 제너릭 View로 바꿨더니 템플릿에서 값이 안 보일 때

특히 `context_object_name`을 확인해야 합니다.

예를 들어 목록 템플릿에서 `songs`를 쓰고 있다면,
아래처럼 정확히 맞춰줘야 합니다.

```python title="music/views.py"
context_object_name = "songs"
```

상세 템플릿도 마찬가지로 `song` 이름이 맞아야 합니다.

---

## 24-5. 수정 후 상세페이지로 이동하지 않을 때

아래 `get_success_url()`을 확인하세요.

```python title="music/views.py"
def get_success_url(self):
    return reverse_lazy("music:song_detail", kwargs={"pk": self.object.pk})
```

이 부분이 없거나 잘못 연결되면 수정/등록 후 원하는 페이지로 이동하지 않을 수 있습니다.
