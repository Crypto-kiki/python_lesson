# 주식 커뮤니티 감정분석 플랫폼 (2) : 종목 목록, 상세 페이지, 종목별 게시글 연결하기

## 이번 편에서 할 일

지난 1편에서는 `stock_sentiment_platform` 프로젝트의 **전체 골격**을 만들었습니다.
즉, 프로젝트/앱 생성, 모델 설계, 관리자 등록, 공통 레이아웃, 홈 화면까지 준비했죠.

이번 2편에서는 그다음 단계로 넘어갑니다.
이제는 **실제 데이터가 화면에 어떻게 보이는지**를 만들어볼 차례입니다.

* 종목 목록 페이지 만들기
* 종목 상세 페이지 만들기
* 특정 종목에 연결된 게시글 목록 보여주기
* `ForeignKey` 관계가 화면에서 어떻게 동작하는지 이해하기
* 다음 편에서 크롤링/수집 기능을 붙일 수 있도록 데이터 구조를 안정적으로 정리하기

즉, 이번 편은 단순히 화면 하나 더 만드는 것이 아닙니다.
**“모델 관계 → View → URL → Template → 화면 출력”** 흐름을 이해해야 합니다!

---

## 1. 왜 이번 편이 중요한가요?

많은 초보자분들이 Django 모델은 어떻게든 만듭니다.
하지만 막상 수업을 진행해보면 아래 부분에서 자주 헷갈립니다.

* `ForeignKey`를 만들었는데 화면에서 어떻게 꺼내야 하는지 모르겠다.
* 종목 1개와 게시글 여러 개 관계를 코드에서 어떻게 연결하는지 모르겠다.
* 목록 페이지와 상세 페이지를 왜 나눠서 만드는지 감이 안 온다.
* 관리자 페이지에 넣은 데이터가 템플릿에서 어떻게 보이는지 흐름이 잘 안 잡힌다.

그래서 이번 편에서는 이 흐름을 파악 할 수 있습니다!

예를 들어,

* 삼성전자라는 종목이 있고
* 그 종목에 연결된 커뮤니티 글이 여러 개 있으며
* 상세 페이지에 들어가면

  * 종목명
  * 종목코드
  * 시장 정보
  * 설명
  * 최근 게시글 목록

이 한 화면에 자연스럽게 보이도록 만드는 것이 목표입니다.

이 작업이 끝나면 이후에 크롤링 데이터를 저장하든,
DRF API를 붙이든,
감정 분석 결과를 연동하든,
모든 기능이 훨씬 쉬워집니다.

## 2. 이번 편 완성 후 화면 흐름

이번 편을 끝내면 대략 아래처럼 동작하게 됩니다.

1. 홈 화면에서 `종목 보기` 메뉴를 누른다.
2. 종목 목록 페이지에서 여러 종목 카드를 본다.
3. 특정 종목 카드를 클릭한다.
4. 종목 상세 페이지에서

   * 종목 기본 정보
   * 해당 종목과 연결된 게시글 목록
   * 게시글 작성일 / 작성자 / 감성 결과(있는 경우)
     를 확인한다.

즉, 데이터가 단순히 DB에만 있는 것이 아니라,
**유저가 직접 눈으로 이해할 수 있는 형태로 정리되는 것**입니다.

## 4. 먼저 모델 관계를 다시 이해해봅시다

1편에서 우리는 아래와 같은 구조를 만들었습니다.

* `Stock` : 종목 정보
* `CommunityPost` : 종목 관련 커뮤니티 게시글
* `DailySentiment` : 날짜별 감성 분석 집계
* `DailyPrice` : 날짜별 가격 데이터

이번 편에서 가장 많이 다루는 것은 이 둘입니다.

* `Stock`
* `CommunityPost`

그리고 핵심 관계는 다음입니다.

* 하나의 `Stock`은 여러 개의 `CommunityPost`를 가질 수 있다.
* 하나의 `CommunityPost`는 하나의 `Stock`에 속한다.

즉,

**1 : N 관계**입니다.

Django에서는 이런 구조를 보통 `ForeignKey`로 만듭니다.

예를 들면,
`CommunityPost` 모델 안에 아래처럼 들어가 있을 겁니다.

```python title="community/models.py (개념 예시)"
stock = models.ForeignKey(
    Stock,
    on_delete=models.CASCADE,
    related_name="posts"
    verbose_name='종목'
)
```

이 코드의 의미는 다음과 같습니다.

* 게시글은 하나의 종목에 연결된다.
* 종목이 삭제되면 해당 종목에 연결된 게시글도 함께 삭제된다.
* 종목 객체에서 `stock.posts.all()` 같은 방식으로 연결된 게시글들을 꺼낼 수 있다.

여기서 `related_name="posts"`가 특히 중요합니다.

왜냐하면 종목 상세 페이지에서 아래처럼 쓰기 좋아지기 때문입니다.

```python title="예시"
stock.posts.all()
```

즉, 이번 편은 사실상 이 관계를 **템플릿에서 자연스럽게 활용하는 연습**이라고 보시면 됩니다.

## 6. stocks/views.py 작성하기

이제 종목 목록과 상세 페이지를 담당할 View를 작성하겠습니다.

이번에는 Django 기본 제너릭 뷰를 사용하면 아주 편합니다.

* 목록 페이지 → `ListView`
* 상세 페이지 → `DetailView`

이렇게 나누면 코드가 깔끔해지고,
초보자도 “목록용 / 상세용” 역할을 쉽게 이해할 수 있습니다.

```python title="stocks/views.py"
from django.views.generic import TemplateView, ListView, DetailView
from .models import Stock


class HomeView(TemplateView):
    template_name = "stocks/home.html"


class StockListView(ListView):
    model = Stock
    template_name = "stocks/stock_list.html"
    context_object_name = "stocks"
    ordering = ["market", "symbol"]


class StockDetailView(DetailView):
    model = Stock
    template_name = "stocks/stock_detail.html"
    context_object_name = "stock"

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context["posts"] = self.object.posts.all().order_by("-created_at")
        return context
```

## 7. stocks/views.py 코드 설명

### 7-1. `HomeView`

이건 1편에서 만들었던 홈 화면입니다.
계속 유지해줍니다.

### 7-2. `StockListView`

```python
class StockListView(ListView):
```

이 코드는 “종목 목록을 보여주는 페이지”라는 뜻입니다.

```python
model = Stock
```

어떤 모델 데이터를 가져올지 지정합니다.
즉, `Stock` 테이블에 있는 데이터를 조회하겠다는 뜻입니다.

```python
template_name = "stocks/stock_list.html"
```

이 데이터를 어떤 HTML 템플릿에 전달할지 정합니다.

```python
context_object_name = "stocks"
```

템플릿에서 사용할 변수 이름입니다.
즉, `stock_list.html` 안에서는 `stocks`라는 이름으로 목록을 꺼낼 수 있습니다.

```python
ordering = ["market", "symbol"]
```

종목들을 시장 기준, 심볼 기준으로 정렬합니다.
KOSPI, NASDAQ처럼 묶여서 보이고, 같은 시장 안에서는 코드 순으로 정리됩니다.

### 7-3. `StockDetailView`

상세 페이지는 특정 종목 하나를 보여줍니다.

```python
class StockDetailView(DetailView):
```

하나의 객체를 자세히 보여주는 전용 뷰입니다.

```python
context_object_name = "stock"
```

템플릿에서 `stock`이라는 이름으로 객체를 사용할 수 있게 합니다.

### 7-4. `get_context_data()`가 중요한 이유

상세 페이지에서는 종목 정보만 보여주면 끝이 아닙니다.
그 종목과 연결된 게시글도 함께 보여줘야 하죠.

그래서 아래 코드가 들어갑니다.

```python
context["posts"] = self.object.posts.all().order_by("-created_at")
```

이 코드 의미는 다음과 같습니다.

* 현재 상세 페이지의 종목 객체는 `self.object`
* 그 종목에 연결된 게시글은 `self.object.posts.all()`
* 최신 글이 위로 오도록 `-created_at` 내림차순 정렬

즉,
**“이 종목에 달린 게시글들을 상세 페이지로 같이 보내라”**는 뜻입니다.

이 부분이 이번 편의 핵심입니다.

## 8. stocks/urls.py 만들기

이제 종목 전용 URL 설정 파일을 만듭니다.

```python title="stocks/urls.py"
from django.urls import path
from .views import HomeView, StockListView, StockDetailView

app_name = "stocks"

urlpatterns = [
    path("", HomeView.as_view(), name="home"),
    path("list/", StockListView.as_view(), name="stock_list"),
    path("<int:pk>/", StockDetailView.as_view(), name="stock_detail"),
]
```

---

## 9. stocks/urls.py 설명

### `path("", HomeView.as_view(), name="home")`

* 메인 홈 화면입니다.
* `/` 주소로 접속했을 때 홈이 열립니다.

### `path("list/", StockListView.as_view(), name="stock_list")`

* 종목 목록 페이지입니다.
* `/list/` 주소로 접속하면 전체 종목 목록을 볼 수 있습니다.

### `path("<int:pk>/", StockDetailView.as_view(), name="stock_detail")`

* 특정 종목 상세 페이지입니다.
* 예: `/3/`
* 여기서 `pk`는 종목의 기본키(PK, id)입니다.

즉, 종목마다 서로 다른 상세 페이지가 자동으로 생깁니다.

## 10. 프로젝트 메인 URL 연결 확인하기

이제 프로젝트 전체 URL에서 `stocks.urls`가 연결되어 있어야 합니다.

```python title="stock_sentiment_platform/urls.py"
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path("admin/", admin.site.urls),
    path("", include("stocks.urls")),
]
```

### 설명

여기서 중요한 점은,
홈 화면도 종목 목록도 종목 상세도 모두 `stocks.urls` 안에서 관리한다는 것입니다.

초반 프로젝트에서는 이렇게 한 앱에서 메인 화면 흐름을 통합해서 관리하는 것이 오히려 이해하기 쉽습니다.

나중에 기능이 많아지면 `community.urls`, `analytics.urls` 등으로 분리하면 됩니다.

## 11. 종목 목록 템플릿 만들기

```html title="templates/stocks/stock_list.html"
{% extends "base.html" %}

{% block title %}종목 목록 | stock_sentiment_platform{% endblock %}

    </div>

{% endblock %}
```

## 12. 종목 목록 템플릿 설명

이 페이지에서는 전체 종목을 카드 형태로 보여줍니다.

### 핵심 포인트 1. 링크 전체를 카드로 감싸기

```html
<a href="{% url 'stocks:stock_detail' stock.pk %}" class="stock-card">
```

이 방식은 UX적으로 좋습니다.
카드 아무 곳이나 눌러도 상세 페이지로 이동하기 때문입니다.

### 핵심 포인트 2. `stock.pk`를 URL에 전달

종목마다 고유 id가 있으므로,
해당 id를 상세 URL로 넘기면 Django가 정확한 객체를 찾아줍니다.

### 핵심 포인트 3. 데이터가 없을 때 예외 처리

```html
{% if stocks %}
```

이런 조건문을 넣어주면,
데이터가 비어 있어도 화면이 깨지지 않고 안내 문구가 보입니다.

이런 처리 습관이 굉장히 중요합니다.

## 13. 종목 상세 템플릿 만들기

```html title="templates/stocks/stock_detail.html"

    <h1>{{ stock.name }}</h1>
    <div class="detail-meta-row">
      <span class="detail-chip">시장: {{ stock.market }}</span>
      <span class="detail-chip">종목코드: {{ stock.symbol }}</span>
    </div>
    <p class="detail-description">
      {{ stock.description|default:"아직 종목 설명이 없습니다." }}
    </p>
  </div>
  <div class="detail-hero__right">
    <div class="summary-card">
      <h3>현재 화면에서 보는 것</h3>
```

## 14. 종목 상세 템플릿 설명

이 템플릿은 이번 편의 핵심 결과물입니다.

### 14-1. 상단 영역

상단에는 종목 기본 정보를 보여줍니다.

* 종목명
* 시장
* 종목코드
* 종목 설명

즉, “지금 어떤 종목 페이지에 들어와 있는지”를 한눈에 알 수 있게 해줍니다.

### 14-2. `posts` 반복문

```html
{% for post in posts %}
```

이 부분이 바로 View에서 넘긴 `context["posts"]`를 출력하는 부분입니다.

즉,

* View에서 게시글 목록을 준비하고
* Template에서 반복문으로 꺼내서 보여주는 구조

입니다.

### 14-3. 감성 결과가 아직 없을 수도 있음

처음에는 게시글마다 감성 결과가 비어 있을 수 있습니다.
그래서 아래처럼 조건문을 사용했습니다.

```html
{% if post.sentiment_label %}
```

이렇게 하면 아직 분석이 안 된 글은
`감성 분석 전` 이라고 자연스럽게 표시할 수 있습니다.

이런 식으로 미래 기능을 고려한 템플릿을 미리 만들어두면,
나중에 감정 분석 기능을 붙였을 때 수정량이 줄어듭니다.

## 19. 자주 만나는 오류 포인트

### 오류 1. `Reverse for 'stock_detail' not found`

이 경우는 보통 URL name이 맞지 않을 때 발생합니다.

확인할 것:

* `stocks/urls.py`에 `name="stock_detail"`이 있는지
* 템플릿에서 `{% url 'stocks:stock_detail' stock.pk %}`로 썼는지
* `app_name = "stocks"`가 있는지

### 오류 2. `'Stock' object has no attribute 'posts'`

이 경우는 `CommunityPost` 모델의 `ForeignKey`에
`related_name="posts"`가 없을 가능성이 큽니다.

즉, 아래 부분을 확인해야 합니다.

```python
stock = models.ForeignKey(
    Stock,
    on_delete=models.CASCADE,
    related_name="posts"
)
```

만약 `related_name`을 다르게 썼다면,
`self.object.posts.all()`도 그 이름에 맞게 바꿔야 합니다.

### 오류 3. 상세 페이지는 열리는데 게시글이 안 보임

이 경우는 보통 두 가지입니다.

1. 해당 종목에 연결된 게시글이 실제로 없음
2. 게시글이 다른 종목에 연결되어 있음

관리자 페이지에서 `CommunityPost`를 열어서,
정말 원하는 종목에 연결했는지 확인해보세요.

### 오류 4. CSS가 적용되지 않음

확인 포인트:

* `settings.py`에 `STATICFILES_DIRS`가 있는지
* `base.html`에 `{% load static %}`가 있는지
* `<link rel="stylesheet" href="{% static 'css/style.css' %}">` 경로가 맞는지
* 실제 파일 위치가 `static/css/style.css`인지

## 20. 이번 편에서 꼭 이해해야 하는 핵심 개념 정리

### 1. ListView와 DetailView의 역할 차이

* `ListView`는 여러 개 데이터를 보여줄 때
* `DetailView`는 하나의 데이터를 자세히 보여줄 때

### 2. ForeignKey 관계를 템플릿으로 꺼내는 방식

* 종목 하나 → 게시글 여러 개
* 상세 페이지에서 `self.object.posts.all()`로 연결 데이터 조회

### 3. URL과 pk 연결 방식

* 종목마다 고유 id가 있으므로
* `<int:pk>` 패턴으로 각 상세 페이지를 쉽게 만들 수 있음

### 4. 비어 있는 데이터도 화면에서 친절하게 처리해야 함

* 서비스는 “데이터가 없을 때”가 더 중요할 때가 많음
* 그래서 `{% if posts %}` 같은 조건문이 중요함
