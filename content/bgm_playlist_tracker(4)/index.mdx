# Django 기초 - BGM 플레이리스트 기록기 만들기(4) : 검색, 필터, 추천 카드, 유튜브 썸네일로 메인 페이지 완성하기

<a href="https://python-lesson-red.vercel.app/blogs/bgm_playlist_tracker(3)" target="_blank">➡️ 이전 교안 보러가기</a>

이번 4편에서는 3편에서 정리한 **제너릭 View 기반 웹 구조**를 바탕으로,
이제 사용자가 곡을 더 편하게 탐색할 수 있도록 **검색 / 필터 / 추천 / 썸네일 기능**을 추가해보겠습니다.

3편까지는 웹 CRUD와 DRF API까지 갖춘 **기본 구조 정리**가 핵심이었다면,
이번 4편은 메인 목록 페이지를 더 실전형으로 바꿔서 **사용 경험을 완성하는 단계**라고 보면 됩니다.

이번 4편에서 새롭게 다룰 내용은 아래와 같습니다.

* 제목 검색 기능
* 가수별 필터 기능
* 별점 높은 곡 추천 카드 영역
* 유튜브 썸네일을 메인 카드 이미지로 사용하기
* 검색과 필터가 함께 유지되는 목록 페이지 만들기

이번 편이 끝나면 사용자는 아래 흐름으로 앱을 사용할 수 있게 됩니다.

```
검색어 입력하기
→ 원하는 제목 빠르게 찾기
→ 가수별로 목록 좁히기
→ 추천 곡 먼저 보기
→ 썸네일이 포함된 카드형 목록 탐색하기
```

즉 3편이 **제너릭 View + DRF API 확장**이었다면,
이번 4편은 **제너릭 ListView 확장으로 메인 화면의 탐색성과 완성도를 높이는 단계**입니다.

# 0. 이번 교안의 진짜 목표

이번 교안의 핵심은 단순히 검색창 하나를 붙이는 것이 아닙니다.

실제로는 아래 5가지를 익히는 것이 중요합니다.

| 목표               | 설명                                                                  |
| ---------------- | ------------------------------------------------------------------- |
| GET 기반 검색 흐름 이해  | 검색어를 query string으로 받아 목록을 바꾸는 흐름을 익힌다                              |
| ListView 확장 경험   | 제너릭 `ListView`를 `get_queryset()`과 `get_context_data()`로 확장하는 법을 익힌다 |
| QuerySet 필터링 익히기 | `icontains`, `filter()`, `distinct()`를 사용해 조건별 데이터를 조회한다            |
| 추천 영역 분리 경험      | 전체 목록과 별도로 추천용 QuerySet을 따로 만드는 법을 익힌다                              |
| 화면 완성도 높이기       | 유튜브 썸네일을 카드 이미지로 사용해 더 실전형 UI를 만든다                                  |

이번 편에서 꼭 머릿속에 남겨야 할 흐름은 아래입니다.

```
사용자가 검색어 입력
→ request.GET 으로 값 받기
→ ListView get_queryset()에서 조건 적용
→ get_context_data()에서 추천 / 가수목록 / 현재 조건 준비
→ 썸네일 URL 생성하기
→ 템플릿에 검색/필터/추천 UI 연결하기
```

이 흐름을 익혀두면 이후 Django에서 만드는 대부분의 **게시글 목록 / 상품 목록 / 영화 추천 / 블로그 검색 페이지**에도 거의 그대로 응용할 수 있습니다.

* 먼저 검색과 필터는 결국 **View에서 데이터가 먼저 정리**되어야 합니다.

즉 이번에도 **데이터 준비 → 템플릿 연결 → 스타일 보강** 순서로 가는 것이 가장 안정적입니다.

# 4. 검색 기능은 왜 GET으로 만들까?

검색 기능은 보통 `POST`보다 `GET`으로 만드는 경우가 많습니다.

그 이유는 아래와 같습니다.

* 검색 결과 URL을 그대로 복사해서 공유할 수 있음
* 새로고침해도 조건이 유지됨
* 브라우저 주소창에 검색 조건이 드러남
* 목록 조회 성격의 기능과 잘 맞음

예를 들면 아래처럼 동작합니다.

```
/?q=love
/?q=night
/?q=blue&artist=아이유
```

즉 이번 교안에서는 검색창에서 입력한 값을 아래처럼 받게 됩니다.

```python title="music/views.py"
query = self.request.GET.get("q", "").strip()
```

이 코드는 주소창의 `?q=검색어` 값을 읽어오는 코드입니다.

# 6. views.py 전체 수정하기

이제 `music/views.py`를 4편 기준으로 전체 수정하겠습니다.

```python title="music/views.py"
from urllib.parse import parse_qs, urlparse

from django.urls import reverse_lazy
from django.views.generic import CreateView, DeleteView, DetailView, ListView, UpdateView

from .forms import SongForm
from .models import Song


class SongListView(ListView):
    model = Song
    template_name = "music/song_list.html"
    context_object_name = "songs"

    def get_queryset(self):
        queryset = Song.objects.all().order_by("-created_at")

        query = self.request.GET.get("q", "").strip()
        selected_artist = self.request.GET.get("artist", "").strip()

        if query:
            queryset = queryset.filter(title__icontains=query)

        if selected_artist:
            queryset = queryset.filter(artist=selected_artist)

        songs = list(queryset)
        attach_thumbnail_url(songs)
        return songs

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)

        query = self.request.GET.get("q", "").strip()
        selected_artist = self.request.GET.get("artist", "").strip()

        recommended_songs = list(
            Song.objects.filter(rating__gte=4)
            .order_by("-rating", "-created_at")[:3]
        )
        attach_thumbnail_url(recommended_songs)

        artists = (
            Song.objects.exclude(artist="")
            .order_by("artist")
            .values_list("artist", flat=True)
            .distinct()
        )

        context["recommended_songs"] = recommended_songs
        context["artists"] = artists
        context["query"] = query
        context["selected_artist"] = selected_artist
        return context


class SongDetailView(DetailView):
    model = Song
    template_name = "music/song_detail.html"
    context_object_name = "song"

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        video_id = extract_youtube_video_id(self.object.youtube_url)
        context["embed_url"] = (
            f"https://www.youtube.com/embed/{video_id}" if video_id else None
        )
        return context


class SongCreateView(CreateView):
    model = Song
    form_class = SongForm
    template_name = "music/song_form.html"

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context["mode"] = "create"
        return context

    def get_success_url(self):
        return reverse_lazy("music:song_detail", kwargs={"pk": self.object.pk})


class SongUpdateView(UpdateView):
    model = Song
    form_class = SongForm
    template_name = "music/song_form.html"

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context["mode"] = "update"
        context["song"] = self.object
        return context

    def get_success_url(self):
        return reverse_lazy("music:song_detail", kwargs={"pk": self.object.pk})


class SongDeleteView(DeleteView):
    model = Song
    template_name = "music/song_confirm_delete.html"
    context_object_name = "song"
    success_url = reverse_lazy("music:song_list")



def extract_youtube_video_id(url):
    if not url:
        return None

    parsed_url = urlparse(url)

    if "youtu.be" in parsed_url.netloc:
        return parsed_url.path.lstrip("/")

    if "youtube.com" in parsed_url.netloc:
        query = parse_qs(parsed_url.query)
        if "v" in query:
            return query["v"][0]

        path_parts = parsed_url.path.split("/")
        if "embed" in path_parts:
            embed_index = path_parts.index("embed")
            if embed_index + 1 < len(path_parts):
                return path_parts[embed_index + 1]

    return None



def build_youtube_thumbnail_url(url):
    video_id = extract_youtube_video_id(url)
    if not video_id:
        return None
    return f"https://img.youtube.com/vi/{video_id}/hqdefault.jpg"



def attach_thumbnail_url(songs):
    for song in songs:
        song.thumbnail_url = build_youtube_thumbnail_url(song.youtube_url)
    return songs
```

# 7. `SongListView` 흐름 하나씩 이해하기

이번 4편의 핵심은 거의 모두 `SongListView` 안에 들어 있습니다.

## 7-1. `get_queryset()`에서 목록 조건 만들기

```python title="music/views.py"
def get_queryset(self):
    queryset = Song.objects.all().order_by("-created_at")
```

제너릭 `ListView`에서는 목록 데이터를 준비할 때 `get_queryset()`을 자주 사용합니다.

즉 3편까지는 기본 `model = Song`만으로 전체 목록을 보여줬다면,
이제는 목록이 단순 전체 조회가 아니라 **조건이 붙는 목록**이 되었기 때문에 `get_queryset()`으로 확장하는 것입니다.

---

## 7-2. 검색어 받기

```python title="music/views.py"
query = self.request.GET.get("q", "").strip()
```

이 코드는 주소창의 `?q=검색어` 값을 가져옵니다.

예를 들면 아래처럼 동작합니다.

```
/?q=love
→ query = "love"
```

`strip()`을 붙이는 이유는 사용자가 앞뒤 공백을 넣어도 깔끔하게 처리하기 위해서입니다.

---

## 7-3. 가수 선택 값 받기

```python title="music/views.py"
selected_artist = self.request.GET.get("artist", "").strip()
```

이 코드는 주소창의 `?artist=아이유` 같은 값을 받습니다.

즉 검색어와 가수 필터는 둘 다 **GET 파라미터**로 관리됩니다.

---

## 7-4. 제목 검색 적용하기

```python title="music/views.py"
if query:
    queryset = queryset.filter(title__icontains=query)
```

여기서 중요한 부분은 `title__icontains`입니다.

의미는 아래와 같습니다.

* `title` → 제목 필드를 기준으로
* `icontains` → 대소문자를 크게 구분하지 않고 포함 검색

즉 제목 안에 검색어가 들어 있으면 결과에 포함됩니다.

예를 들어:

```
검색어: love
결과: Love Dive, My Love, Love wins all
```

이런 식으로 부분 검색이 가능해집니다.

---

## 7-5. 가수 필터 적용하기

```python title="music/views.py"
if selected_artist:
    queryset = queryset.filter(artist=selected_artist)
```

이 코드는 가수명이 정확히 일치하는 곡만 남깁니다.

즉 아래처럼 동작합니다.

```
artist=아이유
→ 아이유 곡만 남김
```

이번 실습에서는 가장 이해하기 쉬운 **정확 일치 방식**으로 구현합니다.

---

## 7-6. 검색 + 필터가 함께 적용되는 이유

아래처럼 필터를 순서대로 이어붙이면,
조건이 누적되면서 자연스럽게 둘 다 적용됩니다.

```python title="music/views.py"
if query:
    queryset = queryset.filter(title__icontains=query)

if selected_artist:
    queryset = queryset.filter(artist=selected_artist)
```

예를 들어:

```
?q=love&artist=아이유
```

이렇게 들어오면,

```
제목에 love가 들어가는 곡
그리고
가수가 아이유인 곡
```

둘 다 만족하는 결과만 남게 됩니다.

이게 바로 조건 조합의 핵심입니다.

---

## 7-7. 왜 리스트로 바꾼 뒤 썸네일을 붙일까?

```python title="music/views.py"
songs = list(queryset)
attach_thumbnail_url(songs)
return songs
```

썸네일 URL은 데이터베이스 필드가 아니라,
유튜브 링크를 이용해 **화면용으로 임시 생성하는 값**입니다.

그래서 QuerySet을 템플릿에 그대로 넘기기 전에,
각 곡 객체에 `thumbnail_url` 속성을 붙여서 넘기면 템플릿이 훨씬 깔끔해집니다.

# 8. 추천 카드용 데이터는 어디서 준비할까?

추천 카드와 가수 목록, 현재 검색 상태 같은 값은 목록 자체와는 별개로 준비해야 합니다.
이럴 때 `get_context_data()`를 사용합니다.

```python title="music/views.py"
def get_context_data(self, **kwargs):
    context = super().get_context_data(**kwargs)
```

이 메서드는 템플릿으로 넘길 추가 데이터들을 준비하는 곳입니다.

---

## 8-1. 추천 카드용 QuerySet 만들기

```python title="music/views.py"
recommended_songs = list(
    Song.objects.filter(rating__gte=4)
    .order_by("-rating", "-created_at")[:3]
)
attach_thumbnail_url(recommended_songs)
```

이 코드는 아래 의미를 가집니다.

* `rating__gte=4` → 별점 4점 이상만 추천 후보
* `-rating` → 별점 높은 순 우선
* `-created_at` → 같은 점수라면 최근 등록 곡 우선
* `[:3]` → 최대 3개만 보여주기

즉 상단 추천 카드는 단순히 아무 곡이나 보여주는 것이 아니라,
**점수가 높고 최근에 등록된 곡 위주로 압축해서 보여주는 영역**입니다.

---

## 8-2. 가수 목록 추출하기

```python title="music/views.py"
artists = (
    Song.objects.exclude(artist="")
    .order_by("artist")
    .values_list("artist", flat=True)
    .distinct()
)
```

이 코드는 아래 의미를 가집니다.

* `values_list("artist", flat=True)` → 가수명만 뽑기
* `distinct()` → 중복 제거
* `order_by("artist")` → 가나다 또는 알파벳 순 정렬
* `exclude(artist="")` → 빈 문자열은 제외

즉 템플릿에서는 이 값을 반복문으로 돌리기만 하면,
등록된 가수 목록을 자동으로 필터 UI에 보여줄 수 있습니다.

---

## 8-3. 현재 검색 상태를 템플릿에 다시 넘기기

```python title="music/views.py"
context["query"] = query
context["selected_artist"] = selected_artist
```

이 값이 있어야 템플릿에서 아래가 가능합니다.

* 검색 input에 기존 검색어 유지
* 현재 선택된 가수 버튼 활성화
* 결과 요약 영역 표시

즉 검색/필터 UI를 만들 때는 **현재 상태를 템플릿으로 다시 넘겨주는 것**이 매우 중요합니다.

# 9. 유튜브 썸네일 URL 만들기

3편에서는 유튜브 링크에서 `video_id`를 뽑아서 iframe 재생에 사용했습니다.
이번 4편에서는 그 값을 다시 활용해서 카드 썸네일도 만들겠습니다.

```python title="music/views.py"
def build_youtube_thumbnail_url(url):
    video_id = extract_youtube_video_id(url)
    if not video_id:
        return None
    return f"https://img.youtube.com/vi/{video_id}/hqdefault.jpg"
```

즉 유튜브 영상 링크가 있으면 아래 형태의 이미지 주소를 만들 수 있습니다.

```text
https://img.youtube.com/vi/VIDEO_ID/hqdefault.jpg
```

이 주소를 카드 이미지로 쓰면,
메인 목록이 훨씬 더 풍부하게 보이게 됩니다.

---

## 왜 `attach_thumbnail_url()` 함수로 분리할까?

```python title="music/views.py"
def attach_thumbnail_url(songs):
    for song in songs:
        song.thumbnail_url = build_youtube_thumbnail_url(song.youtube_url)
    return songs
```

이 함수는 각 곡 객체에 `thumbnail_url`이라는 속성을 임시로 붙여줍니다.

이렇게 해두면 템플릿에서는 아래처럼 훨씬 쉽게 쓸 수 있습니다.

```django title="templates/music/song_list.html"
{% if song.thumbnail_url %}
  <img src="{{ song.thumbnail_url }}" alt="{{ song.title }}">
{% endif %}
```

즉 View에서 한 번 가공해두면,
템플릿이 훨씬 읽기 쉬워집니다.

# 11. 템플릿 구조 하나씩 이해하기

## 11-1. 검색창은 왜 `method="get"`일까?

```html title="templates/music/song_list.html"
<form method="get" class="search-form">
```

검색창은 데이터를 저장하는 것이 아니라 **조건을 전달해서 목록을 조회**하는 역할입니다.
따라서 GET 방식이 자연스럽습니다.

---

## 11-2. 선택된 가수 값을 hidden으로 유지하는 이유

```html title="templates/music/song_list.html"
{% if selected_artist %}
  <input type="hidden" name="artist" value="{{ selected_artist }}">
{% endif %}
```

이 부분이 없으면,
가수 필터를 선택한 뒤 검색을 했을 때 기존 가수 조건이 날아갈 수 있습니다.

즉 이 코드는 **검색과 필터를 동시에 유지**하기 위한 장치입니다.

---

## 11-3. 필터 버튼 링크는 왜 이렇게 만들까?

```html title="templates/music/song_list.html"
href="?{% if query %}q={{ query|urlencode }}&{% endif %}artist={{ artist|urlencode }}"
```

이 링크는 현재 검색어가 있으면 그것을 유지한 채,
가수만 바꾸도록 설계한 것입니다.

즉 아래처럼 동작합니다.

```
현재 검색어: love
가수 필터 클릭: 아이유
→ ?q=love&artist=아이유
```

이렇게 해야 사용성이 좋아집니다.

---

## 11-4. 추천 영역과 일반 목록을 왜 나눌까?

추천 곡은 사용자의 시선을 먼저 끄는 영역입니다.
반면 일반 목록은 전체 데이터를 탐색하는 영역입니다.

즉 역할이 다릅니다.

* 추천 영역 → 우선적으로 보여주고 싶은 곡
* 일반 목록 → 전체 탐색용 목록

실전 서비스에서도 이런 구조는 매우 자주 사용됩니다.

# 15. 자주 만나는 오류 정리

## 15-1. 검색창에 값을 넣었는데 결과가 그대로일 때

가장 먼저 확인할 것:

```python title="music/views.py"
if query:
    queryset = queryset.filter(title__icontains=query)
```

이 코드가 빠졌거나,
`title__icontains` 대신 다른 필드명을 잘못 썼을 가능성이 큽니다.

또는 템플릿의 검색 input 이름이 아래처럼 정확히 `q`여야 합니다.

```html title="templates/music/song_list.html"
<input type="text" name="q">
```

---

## 15-2. 가수 필터를 누르면 검색어가 사라질 때

아래 hidden input 또는 필터 링크의 쿼리 조합 부분을 확인해야 합니다.

```html title="templates/music/song_list.html"
{% if selected_artist %}
  <input type="hidden" name="artist" value="{{ selected_artist }}">
{% endif %}
```

또는 필터 링크에서 `q={{ query|urlencode }}`를 유지하고 있는지 확인해야 합니다.

---

## 15-3. 썸네일이 안 뜰 때

가장 먼저 확인할 것:

```python title="music/views.py"
def build_youtube_thumbnail_url(url):
    video_id = extract_youtube_video_id(url)
```

즉 `extract_youtube_video_id()`가 제대로 `video_id`를 꺼내고 있는지가 핵심입니다.

아래 형태의 링크는 정상 처리됩니다.

* `https://www.youtube.com/watch?v=VIDEO_ID`
* `https://youtu.be/VIDEO_ID`
* `https://www.youtube.com/embed/VIDEO_ID`

하지만 이상한 파라미터가 붙은 링크나 잘못 복사된 링크는 실패할 수 있습니다.

---

## 15-4. 추천 카드가 아예 안 나올 때

추천 조건이 아래처럼 되어 있기 때문입니다.

```python title="music/views.py"
Song.objects.filter(rating__gte=4)
```

즉 별점 4점 이상인 곡이 하나도 없다면 추천 영역이 비어 있을 수 있습니다.
4점 또는 5점 곡을 등록해보고 다시 확인해보세요.

---

## 15-5. 템플릿 에러가 날 때

특히 아래 부분에서 오타가 나기 쉽습니다.

* `{% if selected_artist == artist %}`
* `{{ query|urlencode }}`
* `{% url 'music:song_detail' song.pk %}`

Django 템플릿은 작은 문법 오타에도 바로 에러가 나므로,
괄호나 따옴표, 태그 닫힘 여부를 꼼꼼하게 확인해야 합니다.

self.request.GET.get("artist", "")

---

## 16-2. `get_queryset()`

```python title="music/views.py"
def get_queryset(self):
```

제너릭 `ListView`에서 목록 데이터를 원하는 방식으로 가공할 때 핵심적으로 사용합니다.

---

## 16-3. `icontains`

```python title="music/views.py"

```

문자열 포함 검색을 할 때 매우 자주 사용합니다.

# 18. 결론

이번 4편에서는 3편에서 정리한 제너릭 View 기반 구조를 바탕으로,
BGM 플레이리스트 기록기의 메인 페이지를 한 단계 더 업그레이드했습니다.

이번 편에서 추가한 핵심 기능은 아래와 같습니다.

* 제목 검색
* 가수별 필터
* 별점 높은 곡 추천 카드
* 유튜브 썸네일 기반 카드 UI

즉 이번 편이 끝나면,
이 프로젝트는 단순한 CRUD 실습 예제를 넘어 **직접 탐색하고 즐길 수 있는 플레이리스트 웹앱**에 훨씬 가까워집니다.

이번 시리즈에서 여기까지 왔다면,
이제 Django의 기본 CRUD, 제너릭 View, DRF API, 목록 페이지 확장까지 한 흐름으로 모두 경험한 것입니다.
